# 0007. 평가자용 탐색 콘솔: 슬라이더 입력, 즉시 결정론 렌더, 템플릿 목

상태: 채택 (2026-09-02)

## 맥락
심사자가 결과를 보려면 JSON 프로파일을 손으로 고쳐 CLI를 돌려야 했다. 이 기획의 척추(위계·밴드 시각화,
보호자 문장을 인용하는 질문, 가드레일)는 입력을 바꿔 가며 봐야 드러나는데, 픽스처 목은 프로파일 8종에
고정된 응답이라 임의 입력에는 쓸 수 없었다.
## 결정
`app/explorer.py`(Streamlit)에서 슬라이더·텍스트로 프로파일을 조립해 기존 파이프라인을 그대로 호출한다:
파서(`parse_profile`) → 위기 게이트 → `generate_all` → 가드레일 → `build_report_html`. 슬라이더 변경 시에는
LLM 없이 `build_pending_report_html`로 같은 템플릿의 결정론 부분(곡선·밴드·고정 문구)만 즉시 다시 그린다.
mock 모드는 `TemplateMockClient`(보호자 의견을 「」로 인용, 근거는 준임상 이상 척도만, 첫 시도는 그대로 인용하고
재생성부터 규칙에 걸린 인용을 제외)를 쓰고, 규칙별 위반 시드를 주입해 재생성·폴백을 재현할 수 있다.
종합 지표(내재화·외현화·총 문제행동)는 하위 척도에서 유도하지 않고 직접 입력받는다. 의존성은 `requirements-app.txt`로
분리하고 CI는 코어만 돈다.
## 근거
렌더러·규칙을 JS나 별도 로직으로 다시 짜면 두 벌이 되어 화면과 산출물이 어긋난다. 콘솔은 기존 함수의 호출자일 뿐이어야
한다. 종합 지표는 문항 원점수의 규준 변환값이라 하위 척도 평균으로 만들면 틀린 수치가 되고, 규준 변환은 검사 시스템의
몫이다. PDF 파싱을 두지 않은 것도 같은 이유다 - 실서비스의 입력은 검사 시스템의 구조화 데이터이지 결과지 이미지가 아니다.
## 대안
정적 HTML + JS로 곡선을 다시 그리는 안(렌더러 두 벌), 픽스처 목을 임의 입력에 억지로 맞추는 안(수치·척도 불일치로
가드레일이 오히려 픽스처를 차단), 하위 척도 평균으로 종합 지표를 자동 계산하는 안(규준 변환 왜곡)은 기각.
## 결과
`app/`, `requirements-app.txt`, `tests/test_explorer.py`가 추가되고 `src/llm_client.py`에 `TemplateMockClient`와
`make_client("mock-template")`, `src/report_html.py`에 `build_pending_report_html`이 생겼다. 템플릿 목은 하네스에
쓰지 않으며(픽스처 목 유지) 화면에 "실제 LLM 생성이 아님"을 명시한다. 템플릿 목의 문장은 규칙을 통과하도록 작성된
것이라 실 LLM의 실패 양상(스키마 누락, 코드 누출)을 재현하지 않는다 - 그것은 Ollama/API 모드의 몫이다.

## 추가 결정 (2026-09-02): 입력 패널과 결과 패널의 시각 분리
왼쪽 열은 `st.container(border=True, key="input_panel")`(옅은 회색 배경과 1px 테두리), 오른쪽 열은 `key="result_panel"`(흰 배경과
파란 계열 테두리)로 감싸고, 각 열 맨 위에 번호 배지가 붙은 패널 라벨(입력 / 결과)을 같은 높이에 둔다. 소제목은 입력 패널이
회색 번호 캡션(01~04), 결과 패널이 파란 좌측 보더로 통일해 스크롤 중에도 어느 영역인지 알 수 있게 한다. 색은 리포트 템플릿의
accent 파랑(#4a6fa5) 하나와 회색만 쓰고, 다크 테마에서도 깨지지 않도록 rgba로 지정한다. CSS 셀렉터는 Streamlit이 key에서
만들어 주는 `st-key-*` 클래스와 콘솔이 직접 출력하는 `cb-*` 클래스만 쓰며 `data-testid` 같은 내부 DOM에는 의존하지 않는다
(버전에 따라 바뀔 수 있어 기각). 두 열을 모두 테두리 컨테이너로 감싼 것은 패딩을 같게 해 라벨 높이를 맞추기 위해서다.

## 추가 결정 (2026-09-02): 역할 경계 명시
콘솔은 평가자와 개발자가 파이프라인을 빠르게 확인하기 위한 도구이고 보호자용 화면이 아니다. 슬라이더는 결과 보고서에
인쇄된 수치를 흉내 내는 입력이지 보고서를 편집하는 기능이 아니며, 실서비스에서는 검사 시스템이 넘겨 주는 값이 그 자리에
들어온다. 이 기획은 원 보고서를 고쳐 쓰지 않고 그 위에 동반 가이드를 얹는다는 전제(기획안 1.3)를 따르므로, 콘솔이 보고서
수정 도구로 오해되지 않도록 화면 상단 캡션과 README에 같은 문장을 둔다.

## 보강 (2026-09-03)
- 두 패널의 높이를 같게 맞춘다. 열은 기본으로 늘어나지만 테두리 컨테이너는 내용 높이에 머물러, 생성 전에는 결과 패널이,
  생성 후에는 입력 패널이 먼저 끝나 보였다. 레이아웃 래퍼와 컨테이너 두 층만 flex로 채우는 CSS로 해결한다.
- 보호자 리포트는 자체 CSS와 스크립트를 가진 독립 문서라 iframe에 넣고, Streamlit의 iframe 컴포넌트가 안쪽 높이를
  알 수 없어 고정 높이(980px)에 내부 스크롤을 둔다. 리포트를 전부 펼치면 아래의 실행 패널이 화면 여러 장 밑으로
  내려가므로, 리포트와 실행 결과를 한 화면 근처에 두려는 선택이다.
