# 0001. 태스크당 단일 호출 구조와 결정론·LLM·검증의 3영역 분리

상태: 채택 (2026-09-01)

## 맥락
CBCL 결과를 보호자 해설과 상담 준비 자료로 바꾸는 PoC. 수치 위조·진단·처방이 나가면 안 되고, 3일 안에 검증 가능한 구조여야 한다.
## 결정
기능 2개(explain, prep)를 각각 LLM 호출 1회로 구조화 JSON 전체를 받는다. 코드는 결정론(`src/parser.py`, `src/renderer.py`, `src/report_html.py`),
LLM(`prompts/`, `src/llm_client.py`, `src/generator.py`), 검증(`src/guardrails.py`, `src/quality.py`, `harness/`) 3영역으로 나누고 수치는 결정론 영역에서만 만든다.
## 근거
호출 표면이 작을수록 검증 표면이 작다. 태스크당 1회면 입력(검증된 JSON)과 출력(스키마 JSON)만 검사하면 되고, 재생성도 같은 스키마를
다시 받아 위반 블록만 교체하면 된다. 비용 추정도 호출 2회 기준으로 단순하다 (README '예상 비용').
## 대안
블록별 호출(척도 11개 + 문단마다 호출, 지연·비용 10배 이상)과 에이전트형 다단계·도구 호출(중간 상태가 검증 밖에 놓임)은 기각.
## 결과
LLM은 서술만 맡고 `t_score`/`band`는 입력값 에코로만 허용한다(G3). 그래프·라벨·고지문은 LLM을 거치지 않는다.
재생성 시 스키마 전체를 다시 받으므로 입력 토큰은 블록별 호출보다 많다 (README 실측 표의 in 토큰).
