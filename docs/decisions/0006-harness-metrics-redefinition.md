# 0006. 검증 지표 재정의: 커버리지 2단, FP 게이트, 시드 수 assert

상태: 채택 (2026-09-01, 커밋 eae8617)

## 맥락
초기 하네스의 근거 커버리지는 최종 출력 기준이라 fail-closed 조립 후에는 구조상 항상 100%였다. 클린 프로파일에서의 오검출과 시드 파일이 비는 경우를 게이트가 재지 않았다.
## 결정
1. 근거 커버리지 2단: 원시 attempt 0(가드레일 이전 첫 생성, 생성 품질 지표)과 최종 출력(fail-closed 조립 검증, 구조상 100%)을 따로 표기한다.
2. FP 게이트: 위반 시드가 없는 클린 프로파일(P1~P5)에서 위반 검출이나 폴백이 1건이라도 있으면 불합격이다 (`clean_ok`).
3. 시드 수 assert: 파이프라인 시드와 B축 시드 총수를 상수(`EXPECTED_PIPELINE_SEEDS`, `EXPECTED_B_SEEDS`)로 고정하고 픽스처에서 센 값과 다르면 하네스를 중단한다.
## 근거
구조상 100%인 숫자는 아무것도 재지 않는다. 검출률만 재면 과검출 규칙이 항상 이긴다. 0/0 = 100%는 시드 파일이 비어도 통과하는 구멍이다.
## 대안
최종 출력 커버리지만 표기(폐기), FP를 모니터링 지표로만 두는 안(안전 규칙이 보호자 문장을 지우는 것도 결함이므로 게이트로)은 기각.
## 결과
하네스의 exit code가 합격 게이트가 됐고 CI(`.github/workflows/ci.yml`)가 이를 그대로 쓴다. 이후 추가된 품질 지표 3종(`src/quality.py`)은 게이트가 아니라
표기만 한다. README '평가 결과' 표의 행 구성이 이 정의를 따른다.
