# 0002. fail-closed: 블록 단위 재생성과 안전 문구 폴백

상태: 채택 (2026-09-01)

## 맥락
LLM 출력이 규칙을 어겼을 때 리포트를 안 내보낼지, 일부만 내보낼지, 고쳐서 내보낼지.
## 결정
블록 단위로 검사하고, 위반 블록만 최대 2회 재생성(`MAX_REGEN`)한 뒤 그래도 실패하면 사전 작성 안전 문구로 대체한다(`fallback_for`).
리포트는 항상 나가되 검증 안 된 문장은 나가지 않는다. 입력 단계의 위기 신호는 LLM 호출 없이 상담 연결 안내만 생성하고,
LLM 실패·입력 검증 실패 시에는 산출물을 아예 쓰지 않는다 (`main.py`의 pending 큐).
## 근거
보호자가 받는 문서에서 위반 1건의 비용이 폴백 문구 여러 건의 비용보다 크다. 블록 단위면 통과한 문장은 살리고 실패한 자리만 대체한다.
LLM이 `_fallback` 플래그를 흉내 내 검사를 우회하지 못하도록 입력에서 플래그를 제거한다(`_strip_fallback_flags`).
## 대안
전체 재생성(통과한 블록도 버림), 위반 시 리포트 미발행(상담 전 자료라는 목적 상실), 위반 문장 자동 수정(수정본을 다시 검증해야 하고 모델 의존)은 기각.
## 결과
폴백 발동률이 품질 모니터링 지표가 된다 (README '평가 결과'). 실측에서 프롬프트 개정 후 폴백이 p2 14/17 블록까지 오른 것이 ADR 0005의 출발점이다.
